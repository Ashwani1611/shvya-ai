# Handover construction protocol

## Source ledger

Record current organization, exact tenant IDs, pipeline/stage/attribute/Workflow/Cadence IDs, config revision/read timestamps, channel/sender identities, source requirements, test/review result IDs and returned status. Mark stale, truncated and unavailable evidence. An unverified URL in a prompt does not establish a usable booking or asset route.

## Journey derivation

For each pipeline establish default entry, required qualification, manually owned stages, automatic transitions, loss/opt-out/handoff and outcome states. Derive transitions from actual saved compiled rules and native Workflows. Separate AI generation decision, backend validation, stage update and automation trigger. A source example diagram is never the account graph.

For each node show business definition and AI on/off where observed; for each edge show condition and owner. Use solid edges for verified automatic moves, dashed for documented manual moves, and explicit labeled blocked paths for refused/unsupported moves. Include a human-readable table when graphical style alone could hide the distinction. Keep diagrams compact with at most five horizontal nodes.

## Runtime constraints to expose

- Sender ownership and correct pipeline routing.
- API versus Coexistence versus Hosted versus Instagram behavior.
- Approved templates and resolved header/body/button values for applicable provider paths.
- Real runtime placeholders and missing-value behavior.
- Active settings and suppression after handoff/opt-out/completion.
- Actual file sharing versus indexed retrieval; pending assets and unavailable formats.
- Calendar preference/reminder versus confirmed provider booking.
- Model authority and configured language rules.
- Known queue/provider outage or untested delivery path.

## Readiness labels

Draft: requirements or configuration still incomplete.
Configuration verified: saved state and dependency validators agree.
Engine tested: dedicated no-send production reply/persistence scenarios passed with cleanup verified.
Live delivery verified: separately authorized real transport evidence exists for the exact channel/sender/path.

Use the strongest justified label for each path, not one global green label that hides untested channels. Report required blockers before optional enhancements. Customer approval of copy is not runtime test evidence.
