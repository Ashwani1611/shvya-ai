# Account handover domain checks

Each material claim must have actual configuration or observed evidence and a date/revision. Read complete typed Cadence steps and FAQ/Quick Reply pages. Derive stage graphs from actual rules/manual owners; never infer a transition from an example.

Distinguish API, Coexistence, Hosted and Instagram; template approval/bindings, source readiness and sender routing must be explicit. Do not claim saved asset equals delivered file or reminder equals booked appointment.

Demo steps include Send / Expect / Explain / Evidence with paraphrased expected behavior. Creating a guide does not send, activate or enroll. Use owned fixtures or exact authorized demo targets only.

Report unresolved contradictions, owner/deadline commitments, failed/unexecuted cases and readiness by path. Configuration verified, engine tested and live delivered are different labels.

## Known traps

A mentioned capability is not proof of availability. Do not claim delivery from an isolated test, infer missing client facts, reuse a mismatched approval, or replace configuration from a truncated read. Follow the specific limits and ownership rules above.

## Verification

Read the complete relevant records, compare the expected and saved state, preserve source and audit identifiers, and distinguish unexecuted plans from actual results. Report the domain-specific exclusions and unresolved questions above.
