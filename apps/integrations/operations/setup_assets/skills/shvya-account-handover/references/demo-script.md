# Demonstration script authoring

Prepare a script; do not execute it while writing the handover. Use a fixture or exact authorized test number/account, not a customer selected because it is convenient. State channel, sender, context, source revision and prerequisites.

| Step | Send | Expect | Check in SHVYA | Explain |
|---|---|---|---|---|
| Start | A natural enquiry with one known fact | Grounded welcome once and the first unanswered question | Correct source/pipeline and conversation | Why the system keeps already-provided information. |
| Answer | Eligible answer in natural language or supported option | Acknowledgment plus next unanswered question | Correct attribute key/value | How extraction and descriptions work. |
| Interrupt | A sourced product or pricing question | Allowed answer before continuation | Source trace where exposed | Knowledge and disclosure are different. |
| Compound | Several actual required facts in one message | Skip already-complete fields | Saved values and remaining required fields | One message can satisfy multiple valid fields. |
| Complete | Last required eligible fact | Appropriate acknowledgment without internal jargon | Qualified state and intended stage | Backend criteria govern completion. |
| After close | Related support question | Relevant support without restarting qualification | Preserved stage/state | Later-stage behavior differs from intake. |
| Human | Explicit person/callback request | Authored handoff outcome | Correct state and automation suppression | Human takeover depends on configured policy. |
| Stop | Clear opt-out | Polite close and suppression | Pending/enrolled paths stopped as supported | Consent is respected across automation. |

Add language, file-sharing, template and booking cases only when configured and safe for the selected target. Use paraphrases for expected replies. Real AI wording varies. Include a column with the existing test/evidence reference or label this step unexecuted.

End with fixture cleanup/reset instructions supported by the chosen harness. Do not ask the demonstrator to delete arbitrary leads or reset live organization settings. If the demo needs provider credits or actual outbound sends, its execution requires that exact scope to be authorized separately.
