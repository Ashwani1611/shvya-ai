# Account setup domain checks

## Evidence to inventory
- verified organization context and effective capabilities;
- business/intake sources with provenance and unresolved conflicts;
- complete AI configuration, qualification, CRM schema and automation state;
- channel accounts/routing/settings, knowledge/FAQ/Touchpoints, Calendar/team settings where in scope;
- existing records that should be reused rather than duplicated.

## Known traps
- A template or industry playbook is a starting pattern, not a company fact.
- A polished configuration can still be inactive or unreachable.
- A stage/attribute/sequence existing does not mean downstream dependencies consume it.
- Saving AI/qualification can overwrite adjacent Playbook-owned sections if order is wrong.
- An active Cadence is not automatically enrolled; an enabled Workflow is not proof it has ever fired.
- “Set up everything” does not authorize external sends, test calls or destructive cleanup.

## Verification
Verify dependencies in order: CRM schema → qualification → knowledge/AI → Cadence/Workflow → routing/settings → Calendar/team → acceptance. Read back every changed resource. Run structural validation and deterministic simulations, then use representative provider evidence only when separately authorized.

## Handoffs
Delegate domain decisions to the narrow skill. Finish with `shvya-acceptance-testing`. Use `shvya-incident-repair` only when the task is repairing observed production failure rather than onboarding.
