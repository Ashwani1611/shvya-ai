# Intake vault domain checks

## Evidence
Each intake entry needs source ownership, source ID/reference, source date/time when known, section, evidence status and bounded factual body. Preserve revision history and conflicts.

## Known traps
- Mentioning a brochure does not mean the file was supplied.
- A transcript summary is not equivalent to the source transcript.
- Attachment filenames/captions do not prove contents.
- Reported facts are not automatically confirmed facts.
- Intake is not published AI knowledge and does not authorize CRM/configuration changes.
- Repeated imports with a changed body must update the stable entry identity, not create duplicates.

## Verification
Use revision-aware read → dry-run → approval → apply → read-back. Confirm the intended revision and provenance survived. Keep unresolved questions explicit.

## Handoffs
Approved facts can be proposed to AI Brain/knowledge; process requirements can go to account setup. Publication always uses the destination skill/tool contract.
