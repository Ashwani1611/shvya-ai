# Native Vault domain checks

Native Vault and internal setup intake are different models. Verify actual get_vault output and all 15 sections. Page entries/questions/calls independently; preserve effective client content over agent notes.

Only agent-owned records can be updated; answered questions and client confirmations/overrides are protected. Keep notes <=300 words, stable external_id and true source origin/date. Client-visible questions/calls/uploads use exact preview approval.

Use actual authorized bytes within 512 KiB for uploads; private asset reads expose only safe metadata and supported text preview. Never disclose credentials/signed links or claim unread binary contents. Source upload is not AI publication.

Check source conflicts, missing assets and actual send_when permission. A client-visible section status is not a client confirmation. Read back every authorized change and report coverage/protected fields/gaps.

## Known traps

A mentioned capability is not proof of availability. Do not claim delivery from an isolated test, infer missing client facts, reuse a mismatched approval, or replace configuration from a truncated read. Follow the specific limits and ownership rules above.

## Verification

Read the complete relevant records, compare the expected and saved state, preserve source and audit identifiers, and distinguish unexecuted plans from actual results. Report the domain-specific exclusions and unresolved questions above.
